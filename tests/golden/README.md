# Golden cases — PER-GATE verdicts

Goldens are per **gate**, not per **image**: one render can be geometrically
perfect yet compositionally wrong (e.g. an angle failure), so each case declares
a verdict only for the gates it actually verifies. Gates not listed are ignored
for that case — unverified, never assumed.

## PASS/mixed goldens (preferred)
`tests/golden/pass_<sku>_<slot>/`
- `<slot>_case.png` — the render (user-verified)
- `case.json`:
```json
{
  "sku": "LR-0206", "slot": "04",
  "expect": {
    "G6_primary_ratio": "PASS",
    "G7_setting_elements": "PASS",
    "G2_accent_count": "PASS",
    "G10_angle": "FAIL"
  }
}
```
Gate keys match by G-number prefix (`G6_*` → `G6_STONE_RATIO`).

## Legacy FAIL cases
`tests/golden/cases.json` — single-gate `{gate, expect:"fail", image}` entries; still read (one verdict each). Fixture images are regenerated by `tests/make_fixtures.py` (not committed).

## Promotion (scripts/calibrate.py)
A gate is promotable, over its **declared** cases only, when: FP = 0, catches every declared FAIL, TP > 0, low-confidence < 10%, and at least one PASS verdict exists (else FP is unmeasurable). Flip the flag in `config/gates.json` per gate; record rates in `memory/failures.json`; CI locks it.
